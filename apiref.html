Comprehensive Database Schema & Entity-Relationship Model (ERD)

Conceptual entity mapping and normalized PostgreSQL DDL for the full platform data model.

Entity-Relationship Diagram (Conceptual Mapping)
+-------------------+ 1:N +-------------------+ | SUPER ADMINS / |------------->| ACADEMIES | | EVENT MANAGERS | | (academies) | +-------------------+ +-------------------+ | | | 1:N | 1:N v v +-------------------+ +-------------------+ | TOURNAMENTS | | COACHES | | (tournaments) | | (coaches) | +-------------------+ +-------------------+ | | | 1:N| 1:N| | 0:N (Optional) v v v +--------+ +---------------+ +-------------------+ | POOLS | | BOOKINGS | | SWIMMERS | |(pool_ | | (bookings) |<----| (swimmers) | | cfg) | +---------------+ 1:N +-------------------+ +--------+ | | | 1:N | | 1:N 1:N| v v v +--------------------------------------------+ | EVENT ENTRIES | | (event_entries) | +--------------------------------------------+ | | 1:N v +--------------------------------------------+ | HEAT SHEET ROWS | | (heat_rows) | +--------------------------------------------+
1. Swimmer Accounts Table (swimmers)
CREATE TABLE swimmers ( swimmer_id VARCHAR(36) PRIMARY KEY, full_name VARCHAR(120) NOT NULL, gender VARCHAR(10) CHECK (gender IN ('Boy', 'Girl')) NOT NULL, date_of_birth DATE NOT NULL, sfi_serial_no VARCHAR(50) UNIQUE, parent_name VARCHAR(120) NOT NULL, parent_phone VARCHAR(15) NOT NULL, parent_email VARCHAR(100) NOT NULL, academy_id VARCHAR(36) REFERENCES academies(academy_id) ON DELETE SET NULL, coach_id VARCHAR(36) REFERENCES coaches(coach_id) ON DELETE SET NULL, created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP );
2. Tournaments Table (tournaments)
CREATE TABLE tournaments ( tournament_id VARCHAR(36) PRIMARY KEY, title VARCHAR(200) NOT NULL, state VARCHAR(100) NOT NULL, city VARCHAR(100) NOT NULL, venue_name VARCHAR(200) NOT NULL, start_date DATE NOT NULL, end_date DATE NOT NULL, registration_deadline TIMESTAMP NOT NULL, reg_fee_amount DECIMAL(10,2) DEFAULT 800.00, relay_add_on_fee DECIMAL(10,2) DEFAULT 300.00, allow_swim_up BOOLEAN DEFAULT FALSE, status VARCHAR(20) CHECK (status IN ('DRAFT', 'PUBLISHED', 'CLOSED', 'LOCKED', 'COMPLETED')) DEFAULT 'DRAFT', created_by VARCHAR(36) NOT NULL );
3. Event Entry Master Table (event_entries)
CREATE TABLE event_entries ( entry_id VARCHAR(36) PRIMARY KEY, booking_id VARCHAR(36) REFERENCES bookings(booking_id) ON DELETE CASCADE, swimmer_id VARCHAR(36) REFERENCES swimmers(swimmer_id), tournament_id VARCHAR(36) REFERENCES tournaments(tournament_id), stroke VARCHAR(30) CHECK (stroke IN ('FREESTYLE', 'BACKSTROKE', 'BREASTSTROKE', 'BUTTERFLY', 'MEDLEY')) NOT NULL, distance INT CHECK (distance IN (50, 100, 200, 400)) NOT NULL, category VARCHAR(20) CHECK (category IN ('U10', 'U12', 'U14', 'U16')) NOT NULL, seed_time_ms INT, -- Null or 0 represents 'NT' (No Time) in milliseconds created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP );
4. Heat Sheet Execution Table (heat_rows)
CREATE TABLE heat_rows ( heat_row_id VARCHAR(36) PRIMARY KEY, tournament_id VARCHAR(36) REFERENCES tournaments(tournament_id), pool_id VARCHAR(36) REFERENCES pool_configs(pool_id), event_entry_id VARCHAR(36) REFERENCES event_entries(entry_id), heat_number INT NOT NULL, lane_number INT NOT NULL, finish_time_ms INT, status VARCHAR(10) CHECK (status IN ('OK', 'DNS', 'DNF', 'DQ')) DEFAULT 'OK', dq_code VARCHAR(10) CHECK (dq_code IN ('FS', 'IT', 'IS', 'IK', 'OT', 'LV', 'ET', NULL)), points_awarded INT DEFAULT 0, official_rank INT );

Security, Privacy & Non-Functional Requirements (NFRs)

Compliance, access control, and performance requirements governing the platform.

Security & DPDP Compliance
Child Data Protection (DPDP Act 2023 Compliance)
Since the portal handles minor athletes (U-10 to U-16), explicit consent is captured from parents/guardians during checkout. Minor phone numbers and DOB records are encrypted at rest using AES-256.
Role-Based Access Control (RBAC)
JWT tokens carry embedded role claims (SUPER_ADMIN, EVENT_MANAGER, TOURNAMENT_ORGANIZER, SWIMMER) signed with RS256. API endpoints strictly enforce access boundaries.
Data Integrity & Audit Logging
Immutable administrative audit logs record all manual player additions, category changes, seed time overrides, and timing alterations.
Non-Functional Requirements (Performance & Reliability)
RequirementSpecification
Concurrent Load Handling Supports 5,000+ concurrent connections during tournament opening hours without latency degraded below 500ms API response time.
High Availability (HA) Database runs in Active-Passive multi-AZ replication mode targeting 99.9% uptime.
Off-Line / Weak Network Resilience Poolside result entry forms cache input data in browser IndexedDB local storage, syncing automatically once connection is re-established.
